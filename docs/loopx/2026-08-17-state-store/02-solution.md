# LoopX 单文件状态存储方案

## 结论

在不改变 LoopX 流程契约和控制器命令的前提下，为新运行增加一层透明的状态存储适配：命令执行期间把单个 `run.json` 还原为临时逻辑运行目录，继续调用现有控制器实现；命令成功结束后将全部逻辑文件原子写回同一个 `run.json`。旧项目内运行目录继续由现有代码直接处理。

## 需求与验收标准映射

- AC-01、AC-02：新运行默认定位到用户状态目录，项目内不创建运行目录；静稳状态每个运行只有 `run.json`。
- AC-03、AC-07、AC-08：容器摘要校验、独占锁、同目录临时文件、`fsync` 和原子替换保证损坏可检出、失败不产生部分状态。
- AC-04、AC-05：项目内已有运行或 `LOOPX_STATE_BACKEND=project` 继续走原路径；命令函数和流程判断不改。
- AC-06、AC-09：所有控制器命令、健康检查和项目检查在同一临时逻辑视图中运行，并用完整 FULL 流程回归。
- AC-10：仅使用 Python 标准库，限制目录与文件权限，所有容器条目进行相对路径边界校验。

## 最小方案与备选方案

采用“单文件容器 + 临时逻辑视图”是满足功能不变约束的最小改造。现有阶段、工作项、事件、产物和证据仍以原逻辑文件形式存在，只是物理上被收纳进一个容器，现有业务函数无需改写为新的数据库模型。

未采用 SQLite，因为会引入不同的数据模型、查询与事务语义，扩大兼容风险；未采用压缩归档，因为每个命令都需要随机读取和更新运行状态，且压缩不是当前验收目标；未直接合并现有状态对象，因为这会改变控制器内部契约和严格复核逻辑。

## 数据流和一致性边界

1. 入口解析项目和 run ID，项目内存在旧运行时直接使用旧格式。
2. 新格式命令获取该运行的独占锁，读取并校验 `run.json`。
3. 在系统临时目录还原逻辑文件，并把逻辑运行根注册给现有路径解析函数。
4. 现有命令函数原样读取、校验和修改逻辑文件，输出先写入内存缓冲。
5. 命令正常返回后，扫描逻辑视图、编码内容、计算摘要，以同目录临时文件写入并执行 `fsync`、`os.replace`。
6. 容器提交成功后再向用户输出缓冲内容，最后清理临时目录和锁。

单次命令是存储事务边界。命令异常、容器校验失败或提交失败均不替换原容器，也不输出误导性的成功信息。

## 接口和数据契约

现有 CLI 子命令、参数、返回码、阶段状态、`contract_version`、产物结构和确认语义保持不变。新增环境变量：

- `LOOPX_STATE_DIR`：覆盖用户状态根目录，便于 CI、测试和多工作区隔离。
- `LOOPX_STATE_BACKEND=project`：为新运行显式使用旧项目目录格式，作为兼容与回滚手段。

`run.json` 是内部存储容器，不替代 LoopX 的产物契约。容器包含存储格式版本、项目真实路径、run ID、逻辑文件映射和内容摘要；文本使用 UTF-8，其他内容使用 base64。

## 影响范围

- 新增独立存储模块，负责定位、锁定、容器编解码、摘要和原子提交。
- 控制器入口负责打开存储会话和延迟输出；路径辅助函数把运行内逻辑路径解析到临时视图。
- 健康检查、项目检查、复核和收口通过共用路径辅助函数访问同一逻辑视图。
- 测试默认旧后端以证明原有行为不变，并新增新后端的完整集成测试。
- 文档说明新旧格式的定位、环境覆盖和恢复方法。

## 质量属性

- 简单性：只在入口和路径层增加适配，不重写阶段控制逻辑。
- 模块边界：存储模块只处理物理持久化；控制器仍负责流程语义；项目交付文档仍是普通文件。
- 安全：拒绝绝对路径、父目录跳转和摘要不匹配；状态目录与文件仅当前用户可访问。
- 性能：单次命令顺序扫描一个运行的逻辑文件，当前运行规模较小；不引入压缩或数据库。性能风险未被本次风险模型选中，不设虚构阈值。
- 扩展性：容器格式版本与流程契约版本分离，未来可增加编码或只读导出而不改变流程契约。
- 兼容性：旧目录优先；无版本 v1 和 v2 目录运行不迁移；显式旧后端可立即回退。
- 可靠性：锁避免并发覆盖；校验和发现损坏；原子替换避免半写；旧容器仅在新容器落盘成功后被替换。
- 可观测性：存储错误输出自然中文并包含状态路径或锁位置；调试时可通过显式状态根检查容器，但正常使用无需接触内部文件。

## 失败恢复和回滚

容器加载失败时不执行命令；命令执行失败时丢弃临时视图；提交失败时保留原 `run.json`。异常退出残留的锁会结合记录的进程信息判断，存活写者导致明确拒绝，失效锁可安全回收。

回滚时设置 `LOOPX_STATE_BACKEND=project` 创建旧格式新运行。已存在的新格式运行仍由新存储读取，不做自动降级或删除；旧项目运行始终可继续执行。验证方式为旧回归全量通过，以及新旧运行分别完成状态查询、推进、复核和收口。
