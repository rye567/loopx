# LoopX 低污染状态存储需求

## 用户目标

新的 LoopX 运行不再向项目内写入流程控制 JSON；运行状态改为用户级单文件保存，同时保持现有阶段顺序、风险分级、人工确认、返工、严格复核、健康检查、Git 检查和收口行为。

## 明确约束

- 项目内新增流程控制 JSON 数量默认为 0。
- 新运行使用用户级状态目录和单个 `run.json`。
- 现有事件追踪功能保持，但与其他控制状态一起收纳到 `run.json`，不在项目内生成独立事件文件。
- 项目内人读 Markdown 交付物可继续保留。
- 现有 v1/v2 运行不自动迁移，可继续使用原有命令完成。
- 不新增生产依赖。
- 不执行 commit、push 或发布。

## 验收标准

1. 新运行初始化后，项目下不出现 `docs/loopx/runs/<run_id>` 或其他流程控制 JSON。
2. 用户状态目录中每个运行默认只有一个 `run.json`。
3. 全部现有控制器命令可继续使用，输出语义不变。
4. 状态、工作项、阶段结果、确认、返工、策略快照、健康结果和收口证据在 `run.json` 中保持可复核。
5. 单文件写入使用同目录临时文件和原子替换，失败时不留下部分状态。
6. 严格复核可检测产物、证据、规则快照和确认记录篡改。
7. 没有 `contract_version` 或使用 v2 目录格式的旧运行回归测试通过。
8. 完整新格式流程可从 init 执行到 close，收口后项目内仍无控制 JSON。
