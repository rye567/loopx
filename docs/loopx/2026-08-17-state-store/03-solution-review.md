# 方案审核

## 审核结论

方案满足“降低项目污染且不改变 LoopX 功能”的约束，可以进入测试设计。

## 需求匹配

- 新运行项目内不再创建控制状态目录，物理状态收纳为用户目录下单个 `run.json`。
- 现有命令仍操作同一组逻辑文件，阶段、确认、返工、证据和复核语义不变。
- 旧项目运行目录优先，不迁移、不删除；显式项目后端提供直接回退路径。
- 锁、摘要和原子替换覆盖并发、损坏和提交失败。

## 简单性审核

选择了边界清晰的适配方案：存储层只改变物理布局，命令和流程判断继续复用。相比重写状态模型或引入数据库，该方案修改范围更小，兼容性更容易用原有回归证明。

## 风险与验证要求

- 路径适配遗漏可能让少数子命令写回项目，需遍历全部子命令并断言项目内没有控制 JSON。
- 缓冲输出与容器提交顺序错误可能在失败时误报成功，需注入替换失败。
- 锁回收错误可能造成并发覆盖或永久阻塞，需覆盖存活锁和失效锁。
- 完整流程测试必须包含确认、返工、健康检查、严格复核和收口，不只验证初始化和查询。

## 状态

审核通过；实现必须以原有全量回归和新后端完整流程同时通过为完成条件。
