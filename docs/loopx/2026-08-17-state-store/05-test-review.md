# 测试审核

## 审核结论

测试计划覆盖全部十项验收标准和当前适用规则，包含正常、边界、非法输入、并发冲突、持久化失败、旧版本兼容和完整流程，可以进入开发。

## 清理与隔离审核

- 每个用例使用独立临时项目、状态根和唯一 run ID。
- 清理动作同时删除项目与用户状态目录，并检查锁、临时文件、run ID 和测试前缀无残留。
- 路径越界用例保留外部哨兵并验证内容未变化，避免把“删除成功”误当作边界安全。
- 完整流程结束后先断言运行结果和项目无控制 JSON，再执行清理，避免清理掩盖失败。

## 需要保留的回归证据

- 原有 v1/v2 全量测试必须继续通过。
- 新后端必须有独立的完整 17 阶段测试，不能只复用项目后端夹具。
- 提交失败测试必须比较容器原始字节，并断言没有输出缓冲中的成功结论。
- 跨平台默认目录和权限语义若本地无法覆盖，应明确标记为需要 CI 验证。
