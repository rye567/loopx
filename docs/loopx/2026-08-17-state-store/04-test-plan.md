# 单文件状态存储测试计划

## 测试范围

验证新存储只改变物理布局，不改变 LoopX 的命令、阶段、确认、返工、证据、健康检查、Git 检查、经验记录、严格复核和收口功能；同时验证旧 v1/v2 项目运行继续工作。

## 用例组

### TC-S01 新运行物理布局

- 覆盖：AC-01、AC-02、AC-10。
- 准备：临时项目、临时 `LOOPX_STATE_DIR`、唯一 run ID。
- 执行：运行 `init` 和 `status`。
- 断言：项目内不存在对应运行目录；状态根只有 `run.json`；命令结束无锁或临时文件；文件权限仅当前用户；容器路径均为安全相对路径。
- 清理：删除临时项目和状态根，并断言路径消失。

### TC-S02 容器完整性与原子恢复

- 覆盖：AC-03、AC-07、AC-08。
- 准备：已初始化的有效容器，并保留原始字节。
- 执行：分别篡改内容摘要、模拟命令异常、模拟 `os.replace` 失败。
- 断言：篡改被拒绝；异常和提交失败时原容器字节不变；失败输出为自然中文且不包含先前缓冲的成功结论。
- 清理：恢复或删除测试容器，确认无锁和临时文件残留。

### TC-S03 锁与并发

- 覆盖：AC-07、AC-08。
- 准备：有效运行、一个存活进程锁和一个失效锁。
- 执行：持有存活锁时运行命令；随后验证失效锁回收。
- 断言：存活写者不会被覆盖，命令明确失败；失效锁可安全恢复；任何路径均不存在双写或部分容器。
- 清理：释放锁并删除临时状态根，确认锁文件消失。

### TC-S04 旧运行兼容

- 覆盖：AC-04、AC-05。
- 准备：无 `contract_version` 的 v1 运行、项目内 v2 运行和 `LOOPX_STATE_BACKEND=project` 新运行。
- 执行：运行现有 controller、evidence、health 和 standardization 回归。
- 断言：原参数、返回码、输出语义、阶段结果和严格复核保持；旧目录优先且不创建同名用户容器。
- 清理：沿用每个测试的临时目录清理并验证。

### TC-S05 全部命令路径适配

- 覆盖：AC-05、AC-09。
- 准备：新后端运行以及各命令所需的最小有效产物。
- 执行：覆盖 init、status、interview、spec、mode、next、validate、health、close、git-gate、record-stage、confirm-stage、advance、can-write、fail-review、claim-stage、close-repair、review-feedback、compound 和 validate-learning 等入口。
- 断言：运行内写入都进入容器；项目检查和健康检查能读取新格式；项目内没有流程控制 JSON。
- 清理：删除临时状态根和项目，确认没有测试前缀残留。

### TC-S06 FULL 完整流程

- 覆盖：AC-01、AC-02、AC-05、AC-06、AC-09。
- 准备：临时 Git 项目、唯一 run ID、结构化方案/测试/开发/质量产物和文件证据。
- 执行：仅通过控制器完成 17 个阶段、两次确认、一次真实返工恢复、健康检查、Git 检查、经验记录、严格复核和 close。
- 断言：17 阶段最终为 PASS、工作项收敛、严格复核通过、运行关闭；项目内始终没有流程控制 JSON；状态根静稳时只有 `run.json`。
- 清理：删除临时项目和状态根，确认 run ID 和前缀均不存在。

### TC-S07 二进制与非法路径

- 覆盖：AC-03、AC-10。
- 准备：逻辑视图中加入非 UTF-8 文件，并构造绝对路径、`..` 和重复条目的非法容器。
- 执行：容器往返与非法容器加载。
- 断言：二进制字节完全一致；非法路径在落盘前或加载时被拒绝，不能写出状态根或临时运行根。
- 清理：删除临时文件并验证外部哨兵文件未变化。

## 验收标准与规则映射

所有 AC-01 至 AC-10 均至少由一组自动测试覆盖。`TEST-MAPPING-001` 由结构化映射和可执行断言证明；`TEST-CLEANUP-002` 由每个用例的清理步骤与清理验证证明。

## 环境边界

- 本地：Python 单元和集成测试、完整流程、package 检查、语法编译、diff 检查。
- CI：不同操作系统的用户状态默认目录和文件权限语义需在对应 runner 复核。
- 人工：确认项目工作区不再出现大量控制 JSON，并核对错误信息可理解。
