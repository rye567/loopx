# 开发总结

## 实现结果

新运行默认使用用户级单文件状态存储，现有流程契约和旧运行处理方式保持不变。

## 主要改动

- 新增 `loopx_controller_store.py`，实现跨平台用户状态根、项目标识、`run.json` 编解码、SHA-256 摘要、独占锁、临时逻辑视图和原子替换。
- 控制器入口在新后端命令期间还原逻辑运行目录，命令正常返回后统一提交；提交成功前缓冲用户输出，避免失败时先显示成功。
- `get_run_dir`、`project_path`、规则快照、结构化证据、严格复核、健康检查和项目检查共用逻辑路径解析。
- 新增 `import-artifact`，把编辑后的 interview/spec 等文件收纳到运行容器；`record-stage --artifact-file` 可直接导入结构化 JSON，避免其留在项目目录。
- 项目内存在旧运行目录时继续按 v1/v2 旧格式读写；`LOOPX_STATE_BACKEND=project` 可显式创建旧格式运行，不执行迁移或删除。
- 收口归档失败改为自然中文警告，不再造成已写状态后异常退出；新后端的整次命令由容器提交保证原子性。
- 更新中文和英文说明，明确新旧存储、环境覆盖和逻辑产物导入方式。

## 可靠性与安全处理

- 容器路径拒绝绝对路径、父目录跳转、反斜杠路径和符号链接。
- 容器摘要覆盖格式版本、项目路径、run ID、目录和文件映射；摘要不一致时拒绝执行任何命令。
- 同一运行使用记录 PID 和随机 token 的独占锁；存活写者被拒绝，失效锁可回收。
- 状态目录和文件默认权限分别为 `0700` 和 `0600`。
- 写入先落同目录临时文件并 `fsync`，再 `os.replace`；替换失败保留原容器并清理临时文件。
- 只读命令内容未变化时不重写容器。

代码审查返工补充修复了一组一致性边界：失效锁并发回收不会误删替换后的新锁；回收者中断后可由后续命令安全继续；竞争失败、锁内容非法和 token 越界均不会留下临时所有权文件或 traceback；旧目录模式多产物导入中途失败会回滚已复制文件；审核返回后重做相同阶段时，即使旧阶段结果文件内容相同，也会重新同步已被清除的 state/worklist 状态。
