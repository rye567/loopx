# 最终报告

## 交付结果

LoopX 新运行已改为用户级单文件状态存储。项目内不再创建 `docs/loopx/runs/<run_id>` 或流程控制 JSON；静稳状态下，每个运行在用户状态目录只有 `<project-id>/<run_id>/run.json`。

这次修改没有改写流程模型。原有逻辑 `state.json`、worklist、events、阶段结果、确认、返工、健康结果和收口证据仍由同一控制器生成和校验，只是在命令期间还原到临时视图，成功后原子收纳回单文件。

## 主要实现

- 跨平台用户状态根、项目标识、存储格式版本、UTF-8/base64 编解码和 SHA-256 摘要。
- 同目录临时文件、`fsync`、`os.replace`、延迟成功输出和失败保持原容器。
- 带所有权文件的独占锁，覆盖存活写者、失效锁、并发回收、回收中断和异常清理。
- 路径和 run ID 边界校验，拒绝绝对路径、父目录跳转、反斜杠、符号链接及非法容器拓扑。
- `import-artifact` 与 `record-stage --artifact-file`，让需要编辑的运行产物在不暴露物理目录的情况下进入容器。
- 旧项目目录运行优先；`LOOPX_STATE_BACKEND=project` 可新建旧格式运行；不自动迁移或删除历史运行。
