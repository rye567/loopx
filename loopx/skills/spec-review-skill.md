# 规格审核技能

## 目的

只读审查 `spec.md`，确认需求完整、清晰、可测试，足以进入方案设计。

## 输入

- `spec.md`、`interview.md`、执行等级、风险标签、harness、接口契约和模板。

## 步骤

1. 检查摘要、期望行为、验收标准、范围、边界和测试策略。
2. 查找模糊词、未确认假设和冲突规则。
3. 检查前后端、数据和外部 API 契约清晰度。
4. 判断阻塞性开放问题。
5. 输出 `spec_gate` 和 `stage_result`，不得改实现代码。

## 输出

- `spec_gate.result`、必填字段结论、修正清单和阶段结果。

## 通过标准

- 必填字段满足；验收标准能映射到测试；业务规则无歧义；执行等级有风险理由。

## 失败处理

可修复时返回 `CHANGES_REQUIRED` 且 `return_to: spec_draft`；业务决策缺失返回 `NEED_HUMAN`；风险超出当前等级时回 `mode_selection`。
