# 架构设计技能

## 目的

把需求验收标准映射到最小实现边界。

## 输入

- 已通过的需求产物、项目发现、harness、本次运行的规则快照、风险标签和执行深度。

## 步骤

1. 识别模块、契约、数据、配置和依赖影响。
2. 说明为什么当前方案最简单，并描述目标行为、数据流、控制流和模块边界。
3. 按适用性定义安全、性能、扩展、兼容、可靠性、可观测性、回滚和验证策略。
4. 将设计决策关联到验收标准、规则 ID 或风险标签。
5. 生成符合 `solution.schema.json` 的结构化产物和可同步工作项。

## 输出

- 方案文档、结构化方案产物、写入范围、验证计划、剩余风险和假设。

## 通过标准

- 影响范围明确；八类质量属性都有结论或不适用理由；适用规则有证据；测试策略足够具体。

## 失败处理

范围缺失回需求访谈；模块边界未知回项目发现；高风险未批准时阻塞。
