# 规格生成技能

## 目的

把 `interview.md` 中的已确认事实、开放问题和风险信号转换成可测试的 `spec.md`。

## 输入

- 用户原始需求。
- `interview.md` 或需求采访记录。
- 风险标签、执行等级建议和已知项目约束。
- 当前项目 README、harness、接口约定和测试入口。

## 步骤

1. 提取已确认事实，禁止把未确认假设写成事实。
2. 写明摘要、当前行为、期望行为、范围内和范围外。
3. 把业务规则转换为可观察的验收标准。
4. 写明前端、后端、数据持久化和外部 API 影响。
5. 写明测试策略、发布风险、回滚说明和未关闭问题。
6. 记录执行等级决策输入，并输出 `stage_result`。

## 输出

- `.loopx/runs/<run_id>/artifacts/spec.md`。
- 规格门禁初始结论。
- 带证据和下一步动作的 `stage_result`。

## 通过标准

- 验收标准可测试。
- 范围内和范围外都明确。
- 关键边界情况和错误处理已列出。
- 测试策略能证明核心行为。
- 开放问题为空，或被明确标记为阻塞。

## 失败处理

缺少验收标准、范围、测试策略或关键业务规则时返回 `CHANGES_REQUIRED`。需要用户业务决策时返回 `BLOCKED` 或 `NEED_HUMAN`，并回到 `requirement_interview` 或 `spec_draft`。
